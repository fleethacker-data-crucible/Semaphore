# Changelog

## Unreleased

- **SQL scripts on the local database** (SQL desk > Script; docs/LOCAL-DATABASE.md): several statements in your own SQL language, run in the local database in one transaction, with the translated SQLite script and its notes shown first, a result tab per statement, Ctrl+Enter, parameters asked for before the run, history, name suggestions from the local tables, and a saved-scripts library on the server (`SEMAPHORE_HOME\scripts`). T-SQL and Oracle `MERGE`, `PIVOT` / `UNPIVOT`, `TRY...CATCH` and `BEGIN...EXCEPTION` (savepoints), variables, `IF` / `WHILE` / `FOR` (bounded), `SELECT ... INTO` and more are translated; `ATTACH`, pragmas that set, `VACUUM INTO`, `load_extension`, triggers and any write to Semaphore's own tables are refused by an authorizer on a write path of its own (the query path stays read-only). Live databases stay read-only: `IMPORT INTO t FROM SOURCE id AS (SELECT ...)` copies rows through the guarded read path.
- **Pipelines** (Data > Sources > Pipelines; docs/PIPELINES.md): ordered Import, Script, Pull and Publish steps that rebuild tidy local tables, shown as boxes with each step's last state, rows and time. Update now runs all of them or from a step; an unchanged source is skipped unless forced; every table is swapped in whole, so a failed run never leaves half a table. Hourly, daily or weekly schedules run in the server (one run at a time; catch up once at start-up if asked), and `Semaphore-CLI.bat pipeline run <id>` runs them from Windows Task Scheduler without administrator rights. Publish marks the snapshots that read the tables as out of date.
- **Dataset exports**: a whole local table (from the local tables list, or a Table flag's inspector) as CSV, Parquet, a one-table SQLite file or Excel (at most 1,048,576 rows, with a note), written on the server and streamed as a download; also `local export` on the CLI.
- **TalkForge starts when speech is needed, as in Lazarette**: spoken answers no longer need `talkforge serve` running first. When an answer, **Test voice**, the speaker button or a click on the orb needs speech and nothing answers on the TalkForge address, Semaphore starts TalkForge (`node tools\talkforge.mjs serve` on the configured port, stopping by itself after 30 idle minutes) and says *Getting the voice ready* in the panel, in Test voice and on the orb. A TalkForge already running, such as one Lazarette started, is used as it is and never started twice. The token goes only into TalkForge's environment, never on its command line, and Semaphore stops the TalkForge it started when it stops. `config\settings.json` has `voice.autoStart` (on) and `voice.folder` (or `SEMAPHORE_VOICE_FOLDER`; empty finds TalkForge next to Semaphore or in your Projects folder). New `GET /api/voice/status` and `POST /api/voice/start`. See docs/VOICE.md.

- **Local database for big files** (docs/LOCAL-DATABASE.md): Data > Sources has **Add to local database**. Pick or drop CSV, TSV, TXT, Excel (.xlsx), SQLite (.sqlite, .db), Parquet or Arrow files (also .gz), or type a path or a network path, and Semaphore loads them into a database on this computer, \<home>\local\warehouse.sqlite\, in the SQLite engine that ships with Windows (\winsqlite3.dll\): nothing to install. Tables of 10 million rows and more are then queried on the server like any other source (the built-in \local\ source, read-only on the query path) and profiled into the catalog with **Profile and add**. The CSV reader handles quotes, embedded line breaks, byte-order marks and UTF-16, guesses the delimiter, and infers numbers, booleans and ISO dates, widening a column when later rows need it; 2 million rows import in about 2 s on a workstation (about 1M rows/s). Uploads stream to disk (up to 20 GB, settings \localImportMaxGB\) and imports run on their own runspace with progress, a Stop button, an atomic replace and an append that matches columns by name (a taken name otherwise gets a suffix, never overwritten), so the page and other queries stay responsive. Network shares are opened only for servers listed in settings \localShares\, because opening \\\\server\\share sends the user's Windows sign-in to that server; links and mapped drives are resolved and checked first. The CLI has \local list\, \local import\, \local sheets\, \local status\, \local rename\ and \local delete\, and \Import-SemLocalFile\ is the one entry point the routes and other connectors share.
- **Pivot tables** (Pivot, next to Table in the palette): every field but the last makes the rows, nested in order, and the last field makes the columns, with the measures side by side under each column; one field makes a one-way table. Subtotals per outer group, a total column, a grand total row, groups that fold and unfold (a button with aria-expanded), sticky headers, horizontal scroll and a 200-column cap with a note. Click a measure header to order the rows by that column (or by the total), the corner to order them by name; the inspector's Pivot panel sets each measure to values, % of row, % of column or % of total, and the starting order of rows and columns. Heat shading per measure (off, by row, by column, whole table) is in the Look panel and uses the look's palette. A click on a row or column header filters the page or drills, as a table row does. Totals are only added up where that is right: sums, counts, minimums and maximums come from their cells, while averages, distinct counts and anything split by a many-side field are read from the data grouped by fewer fields (one extra query per grouping, through the same cache and cross-filtering), and shown as a dash with the reason when they cannot be read, never summed. Drafting picks a pivot from "pivot", "crosstab", "matrix of" and "by X across Y". CSV, Excel and the other exports carry the pivoted grid with its subtotals and totals, in the order the page shows. The maths is a pure module, src/core/pivot.ts, with 19 tests.
- **Page snapshots** (Hoist > Snapshots…, or Ctrl+K): save the page as it is with a name and a note, see the saved ones with when and by whom, look at one without changing anything (its layout drawn small, what restoring would bring back, take away or change, and a note when the catalog has changed since), restore it, or delete it (to .trash). Restoring first saves the page as it is now, so a restore can be undone, and Undo takes it back too. Semaphore also takes one before Redraft whole page, Tidy up, a layout change and flying a kit, at most one every 10 minutes per page, keeping the last 30 of those and every named one. They live in the Semaphore folder under snapshots\<hoist id>, the page byte for byte with a small file saying what it is (`/api/page-snapshots`, browser-only in the command list).

- **Amazon RDS and Aurora sources** (docs/CONNECTORS.md): `"kind": "aws-rds"` with an `engine` (`postgres`, `aurora-postgresql`, `mysql`, `mariadb`, `aurora-mysql`, `sqlserver`, `oracle`), `host`, `port`, `database` and `region`. Semaphore builds the ODBC connection string from the driver already on the computer (psqlODBC, MySQL Connector/ODBC or MariaDB, ODBC Driver 18/17 for SQL Server, Oracle Instant Client) with TLS required, and when the driver is missing says which one to ask IT for; it installs nothing. Sign in with a password from Lazarette, or with `"auth": "iam"` (PostgreSQL, MySQL, MariaDB): a 15-minute RDS IAM auth token signed in memory with the AWS session from Lazarette, never logged. Sessions are read-only where the engine allows it (PostgreSQL, MySQL; `ApplicationIntent=ReadOnly` on SQL Server). GovCloud regions and FIPS endpoints work. The engine picks the SQL dialect (`dialectForSource`); `mysql` is now a dialect name, with its SQL rendering coming in the MySQL dialect work. The Data panel's RDS card explains the entry and **Find RDS databases** lists a region's instances and clusters with an entry to copy (Semaphore does not write `sources.json`).
- **Amazon S3: browse and import.** The Data panel's Amazon S3 section browses the buckets and prefixes allowlisted in `config\settings.json` (`s3.buckets`; anything else is refused), and imports picked objects or a whole partitioned folder (up to 2000 CSV, JSON lines or Parquet parts with the same columns) into the local database, with progress. Objects are streamed to disk, never held in memory, pinned to their ETag, size-checked and expanded from `.gz`; the size limit is `s3.maxObjectMb` (20480 by default). The AWS session comes from Lazarette (`aws.vault`) or the environment. It loads only when the Data panel opens, so the start of the page did not grow past its budget.

- **Custom chart widgets** (palette: More charts > Custom): write your own chart code against the flag's data. A custom flag drafts its data from the brief like any other, then runs `render(api)` with the rows as plain columns and values, the page's colours, the full ECharts library, `api.select(field, value)` to filter the page, and `api.format` / `api.label` for numbers and dates as the page shows them. The inspector's Widget panel has a code and CSS editor (line numbers, Tab indents, Esc leaves), three working templates for fleet data (Bullet chart: actual against target over poor, fair and good bands; Gantt timeline: items from start date to end date or for their days open; Small multiples: one small chart per region or class, on one scale), the error and its line under the code, and a team library: **Save to team library** and **Insert from library** keep widgets as JSON files in the Semaphore folder's `widgets` folder (`GET/POST /api/widgets`, `GET/DELETE /api/widgets/<id>`; names cleaned, code at most 64 KB, CSS 16 KB, 500 widgets). The code runs in `<iframe sandbox="allow-scripts">` on `/sandbox/widget.html`, an opaque origin under its own CSP (`sandbox allow-scripts; default-src 'none'; script-src 'self' blob:; ... frame-ancestors 'self'`). The code runs as a blob: script the frame makes from it, never through eval, so the frame has no 'unsafe-eval': it cannot read the page's session token, storage or DOM, and has no network at all. Messages both ways carry a per-frame nonce and are checked for origin, window and shape; a widget can only select values of its own fields. A widget stuck in a loop freezes only the widget frames (the browser runs them in one sandbox process), never the page: a watchdog takes them down, says "This widget stopped responding" on the one to blame, and starts the others again one at a time. A custom widget exports as its table and, while it is drawn on the page, its picture. The page's CSP adds `frame-src 'self'`; the frame's bundle (ECharts and the bridge) is built apart and never loads with the page.

## 0.2.0 (2026-10-26)

Semaphore becomes a tool you can use: a local server, a browser UI, and intelligence that needs no model.

### Run it
- `Launch-Semaphore.bat` starts the PowerShell 5.1 loopback server (TcpListener on 127.0.0.1, port block 8774-8776) and opens the page. Every TechStack lifecycle rule: heartbeat and auto-stop, End session, `Stop-Semaphore.ps1`, one instance, runtime file, `SEMAPHORE_AUTO_STOP=0`.
- Hoists and catalogs autosave to the user's Semaphore folder. Without a server the page still works on sample data and CSV files and saves in the browser.

### Data
- Sources: the fleet-maintenance example with generated sample rows, CSV files read in the page (never uploaded), and ODBC / OLE DB sources listed in `sources.json` (DSN or integrated authentication; passwords in connection strings are refused).
- Profiling a table or a CSV file proposes a catalog: labels and synonyms from column names ("hull_no" reads as "Hull number" and answers to "hull"), row counts, totals of amounts, averages of durations and rates, distinct counts of identifiers, and identifiers or years kept as fields rather than added up.
- An in-memory engine answers page-held sources with exactly the query a database would get, so flags behave the same on a CSV file and on Oracle.

### Building a page
- Canvas: drag flags from the palette, move and resize on the 12-column grid, arrow keys to nudge (Shift to resize), Delete, undo and redo.
- Brief boxes highlight what Semaphore understood as you type: measures, fields, time, ranking, behaviour, colour rules, comparisons. Unknown words are underlined; typos get "did you mean", and picking one teaches the catalog the word.
- Smart flag: describe it and Semaphore picks the chart from the data's shape. More than 15 categories are cut to the top 15 and the flag says so.
- Ask a question ("Which ship class had the most work orders?") and pin the answer.
- An empty page offers a starter page drafted from the catalog, and example briefs written with the catalog's own names.
- Flags flip over to a plain-English readback, notes and the exact SQL with its parameters.
- Insights on each flag: the latest move in a trend (a period still running is not compared), a dominant category, an outlier, the biggest move against the comparison window, values breaking a red rule.

### Model
- `binding.compare`: `previous-period` or `previous-year`, like for like against a "last N" window, with time values lined up period by period.
- `binding.share`: values as a share of the total, taken before any top-N cut.

### Local rules
- Questions ("which X had the most Y"), comparisons ("vs last year", "growth"), shares ("% of total").
- A word two tables share resolves to the table the rest of the brief points at.
- "Clicking a bar filters the page" no longer forces a bar chart.
