Build the dashboard by describing it

Semaphore is a Qlik-style dashboard builder for thin clients, with AI doing the heavy lifting. Drop a flag on the page, say in plain English what it should show, and Semaphore wires the data, picks the chart and writes the SQL. It learns how your team builds, so it can carry the routine work while you're out. Nothing to install, no admin rights.

Porting from Qlik · in review

Bring your Qlik app with you

Your Qlik app already knows what the data means. Open Data → Import from Qlik, paste its load script and chart expressions, map each connection to a source, and pick the tables. Semaphore reads it all with no model needed for the common cases, profiles the real tables, and shows you everything before it reaches the catalog. Expressions it can't read, the AI can read for you, checked against your catalog before anything is added.

No black boxes

Flip any flag over and read its SQL

What you can trust about it

  • Table and column names come only from the catalog, always quoted.
  • Every value is a bound, typed parameter: $1 on Postgres, :p1 on Oracle, @p1 on SQL Server, ? on Access.
  • Dates are bucketed in UTC; a date's upper bound covers the whole day.
  • Where a database can't do it right (Access has no COUNT(DISTINCT)), Semaphore refuses rather than guess.
  • Every draft carries a confidence score and notes on what it could not match.
-- Labor cost by region, last 12 months (Postgres; illustrative)
SELECT "region",
       "ship_class",
       SUM("labor_cost") AS "labor_cost"
FROM   "jobs"
WHERE  "opened" >= $1
  AND  "opened" <  $2
GROUP BY "region", "ship_class"

-- $1 = 2025-11-01 (date)   $2 = 2026-11-01 (date)

Messy data · built, in review

The load-script work, done with you instead of by you

Cleaning data and wiring tables together is where a lot of Qlik time goes. Semaphore finds the mess (the AI adds the abbreviations and misspellings, when asked) and proposes each fix; you approve each one, and Semaphore applies it in its own code, so the AI never touches the numbers.

Spots the mess

"N.E." next to "Northeast", stray spaces, mixed date formats, numbers stored as text, duplicates, blanks that mean zero.

Readable cleaning steps

Each fix is a plain sentence you can read, accept or undo: "Treat N.E. and NE as Northeast". No script to maintain.

Finds the joins

Proposes which tables connect on which keys, with how many values actually match, so a flag can read across tables and drill from ship class to hull to the rows behind it.

Checked, then shared

Accepted steps live in the catalog, so every analyst and every snapshot gets the same clean data.

Databases

Postgres (including Postgres on AWS), Oracle and SQL Server through ODBC, with SQL written in each one's own dialect and every value a bound parameter.

Works today

The S3 data lake, built in

Sounding Line's lake engine becomes Semaphore's Athena source: before a flag's query runs, Semaphore sizes the table and shows the most it could scan and cost. Big scans wait for a Run it click, a missing partition filter gets a warning, daily limits hold, and repeat queries come from the cache for free. Adding a lake table reads the catalog only and costs nothing.

Why the lake and Semaphore fit

Every flag is one aggregate query, so a scan returns a few hundred rows, not millions. Snapshots mean leadership's questions are answered from saved results and never start a scan of their own. Credentials stay in the DSN, Windows sign-in or the broker, never in the page.

Bridges from Qlik

Reads what the script reader can't: ratios, nested aggregates and calculated fields. See "Bring your Qlik app with you" below.

Local or cloud, your call

Semaphore talks to AI through Fairlead, the Fleet's model router: a local model by default, so prompts stay on the computer, or an approved cloud model with one setting. Prompts carry briefs and catalog labels only, never data rows. SQL is written by Semaphore's own code from a checked draft, so a model can never invent a figure. With no model at all, the built-in rules still draft every flag.
